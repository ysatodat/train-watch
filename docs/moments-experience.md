# Moments Experience

## Product shift
「次の電車まで」だけでなく、駅で起きる **到着・停車・発車・通過** を「見どころ」として扱う。

## Core UX
- Hero は、駅全体の「次の見どころ」を1つだけ大きく表示する。
- その下の「いま・もうすぐ」は、最大3本の列車を同時に表示する。
- 列車ごとに状態を独立管理するため、上下線の列車が近接しても上書きしない。
- 75秒以内に複数の別列車が見どころになる場合は「レアタイム」として強調する。

## Train state model
### 停車列車
1. 到着の目安
2. 到着中
3. 発車の時間帯
4. 発車済み

公開時刻は分単位なので、発車秒を断定しない。到着は駅間モデルからの目安。

### 通過列車
1. 接近
2. 通過中
3. 通過済み

## Observation interaction
現地の親子が実際の電車を見て状態を補正できる。
- `いま停まった！` → その列車を端末内で停車中として保持
- `動いた！` → 発車を見られた記録
- `見えた！` → 通過を見られた記録

記録は端末内 localStorage のみで、日付が変わるとリセットする。

## Multiple trains
画面の主役は1つに保ちつつ、情報は複数列車を並列表示する。
これにより認知負荷を上げず、2本同時のようなレアな状況は見逃さない。

## Accuracy policy
- 秒単位の公開情報がないものを秒精度で断定しない。
- 発車は「時間帯」、到着・通過は「目安」と明記する。
- 遅延・運休・臨時列車は現在のPages版では反映しない。
- 実際の電車を優先して見るための補助ツールであることを維持する。

## Microinteraction
- 到着: 電車が入ってきて止まる動き
- 発車: 停車中の小さな予兆、`動いた！`で加速して画面外へ
- 通過: 短く速く走り抜ける
- レアタイム: 2本のミニ車両が別レーンで交差
- `prefers-reduced-motion` では動きを停止する
